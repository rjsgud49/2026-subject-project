슬라이드 **「개선사항」** 항목별로 **어디서 시연하는지**, **계정·URL**, **추천 순서**를 정리했습니다.

## 시연 환경 선택

| 환경 | URL | 용도 |
|------|-----|------|
| **운영 (권장)** | https://olp.rjsgud.com | 배포·PM2·PG 결제·HTTPS return URL 시연 |

## 1. 배포

### 1-1. GitHub Actions → EC2 자동 배포

- **설명 위치**: `.github/workflows/deploy.yml`
- **시연 방법** (말로 + 화면):
  1. GitHub 저장소 → **Actions** → **Deploy to EC2** 워크플로 실행 이력
  2. `main` push 시 SSH로 EC2 접속 → `git pull` → 백엔드 빌드 → `pm2 restart` → 프론트 빌드
  3. 브라우저에서 https://olp.rjsgud.com 접속 → 배포 결과 확인

```bash
# EC2에서 (SSH)
pm2 status
curl -s http://127.0.0.1:3000/api/v1/health
```

### 1-2. PM2 백엔드 상시 운영

- **설정 파일**: `p3/backend/ecosystem.config.cjs`
- **시연**: EC2 터미널에서 `pm2 status`, `pm2 logs p3-backend --lines 30`

### 1-3. Docker 로컬 DB

- **파일**: `p3/docker-compose.yml`
- **시연** (로컬 터미널):

```bash
cd p3
docker compose up -d
cd backend && npm run seed && npm run start:dev
cd ../frontend && npm run dev
```

## 2. 운영·관리

### 2-1. 메트릭 · 감사 로그

| 항목 | 경로 |
|------|------|
| UI | **관리자** → **운영·모니터링** (`/admin/ops`) |
| API | `GET /api/v1/admin/ops/metrics`, `GET /api/v1/admin/ops/audit-logs` |

**시연 순서**

1. `admin@p2.local` 로그인 → `/admin` → **운영·모니터링**
2. **메트릭**: uptime, HTTP 요청 수, 오류율 확인 (15초마다 갱신)
3. 페이지 이동·API 호출 후 숫자 변화 확인
4. **감사 로그**: 역할 변경, Webhook 등록 등 관리자 행위 기록 확인

### 2-2. 알림 (이메일 · Discord)

| 항목 | 경로 |
|------|------|
| UI | `/settings/notifications` (내 강의실 상단 링크) |
| API | `GET/POST /api/v1/notifications/subscriptions` |

**시연 순서**

1. `student@p2.local` 로그인 → **내 강의실** → **알림 구독 설정**
2. **Discord** 채널 선택 → Webhook URL 입력 (Discord 서버 설정에서 발급)
3. 이벤트 `payment_success`, `feedback_answered` 선택 → 저장
4. 아래 **2-4 테스트 이벤트** 또는 실제 결제·피드백 답변으로 Discord 메시지 수신 확인
5. 이메일: 서버에 `SMTP_HOST` 등 설정 시 실제 발송, 없으면 백엔드 로그에 `[email→...]` 출력

### 2-3. Webhook (HMAC `X-P3-Signature`)

| 항목 | 경로 |
|------|------|
| UI | `/admin/ops` → Outbound Webhook 등록 |
| 헤더 | `X-P3-Event`, `X-P3-Signature: sha256=<hmac>` |

**시연 순서 (webhook.site 사용 — 가장 쉬움)**

1. https://webhook.site 에서 고유 URL 복사
2. `admin@p2.local` → `/admin/ops` → 이름·URL 입력 → **Webhook 등록** → **secret** 복사 (한 번만 표시)
3. **테스트 이벤트 발송** → `payment_success` 선택 → 발송
4. webhook.site에서 POST 본문 + `X-P3-Signature` 헤더 확인

**로컬 검증 스크립트** (secret 알 때):

```bash
node p3/scripts/demo-webhook-receiver.mjs
# 다른 터미널에서 ngrok 등으로 공개 URL 연결 후 /admin/ops에 등록
```

### 2-4. 스케줄 (pending 결제 만료 · 미답변 피드백 알림)

| 항목 | 설명 |
|------|------|
| 코드 | `p3/backend/src/ops/scheduler.service.ts` |
| 운영 | pending 결제 **24시간** 후 failed (매시), 미답변 피드백 **매일 09:00** 알림 |
| 시연 UI | `/admin/ops` → **스케줄 (시연)** 버튼 |

**시연 순서**

1. (선택) 학생으로 유료 강의 결제창까지 진행 후 **결제 완료하지 않음** → pending 주문 생성
2. 관리자 `/admin/ops` → **pending 주문 전부 만료 (시연)** 클릭
3. **스케줄 실행** → 미답변 피드백이 있으면 강사에게 `pending_feedback_reminder` (구독 시 Discord/이메일)

## 3. 비즈니스 기능

### 3-1. 온라인 결제 (장바구니 → PG → 수강 등록)

| 항목 | 경로 |
|------|------|
| 강의 목록 | `/courses` |
| 장바구니 | `/cart` |
| 무료 강의 | 가격 0원 → 장바구니에서 즉시 수강 등록 |
| 유료 (PG) | 운영 URL + `PAYMENT_*` 키 설정 시 카드 결제 |

**시연 순서 (운영 PG)**

1. `student@p2.local` 로그인
2. `/courses` → **TypeScript로 배우는 백엔드 기초** (49,000원) 등 → 장바구니
3. `/cart` → 결제 → PG 창 → 완료 → `/checkout/complete` → `/dashboard` 수강 확인

**로컬 (PG 없이)**

- 가격 **0원** 강의만 `free-checkout`으로 시연
- 또는 운영 https://olp.rjsgud.com 에서 PG 시연

```bash
curl -s https://olp.rjsgud.com/api/v1/payments/config
# enabled:true 이면 PG 사용 가능
```

### 3-2. 피드백 이용권 (구매 → 신청 시 차감)

| 항목 | 경로 |
|------|------|
| 홈 | `/feedback` |
| 구매 | `/feedback/buy` |
| 신청 | `/feedback/new` |
| 내역 | `/feedback/history` |

**시연 순서**

1. `student@p2.local` → **피드백** 메뉴 → **이용권 구매** (`/feedback/buy`)
2. 플랜 선택 → 결제(또는 PG) → 잔여 횟수 확인 (`/feedback` 홈)
3. **피드백 신청** (`/feedback/new`) → 플랜 선택 → 제출 → **1회 차감** 확인
4. `teacher@p2.local` → **강사 스튜디오** → 피드백 답변 → 학생 알림·이벤트 발생

### 3-3. 강사 정산 (매출 원장 · 정산 UI)

| 항목 | 경로 |
|------|------|
| 대시보드 | `/teacher` (매출·예상 정산 요약) |
| 정산 상세 | `/teacher/settlement` (계좌 정보 + 수익 원장 테이블) |
| API | `GET /api/v1/teacher/settlement/ledger` |

**시연 순서**

1. `teacher@p2.local` 로그인
2. **강사 스튜디오** → 대시보드에서 매출·수수료·정산액 카드 확인
3. **정산** 메뉴 → 계좌 저장 + **수익 원장** (수강 1건당 한 줄, DB 스냅샷)
4. (선택) 학생이 유료 강의 수강 신청 후 원장에 새 행 추가되는지 확인

### 3-4. 리뷰 검수 (승인 후 랜딩 노출)

| 항목 | 경로 |
|------|------|
| 랜딩·리뷰 작성 | `/` (하단 리뷰 섹션) |
| 관리자 검수 | `/admin/reviews` |

**시연 순서**

1. 로그인한 학생 → `/` 스크롤 → **리뷰 남기기** → 등록 (검수 대기 메시지)
2. 랜딩 **수강생 후기**에 아직 안 보이는지 확인
3. `admin@p2.local` → `/admin` → **리뷰 검수** → **승인**
4. `/` 새로고침 → 후기 목록에 노출 확인

## 추천 시연 시나리오 (약 15분)

1. **배포** (1분): Actions 로그 + https://olp.rjsgud.com 오픈
2. **결제** (3분): 학생 장바구니 → PG → 내 강의실
3. **이용권** (2분): 구매 → 신청 → 차감
4. **강사 정산** (2분): teacher 정산 화면·원장
5. **리뷰 검수** (2분): 학생 작성 → admin 승인 → 랜딩
6. **운영** (5분): admin `/admin/ops` — 메트릭, Webhook + 테스트 이벤트, 스케줄, 감사 로그
7. **알림** (1분): `/settings/notifications` Discord 구독 + 테스트 이벤트

## 문제 해결

| 증상 | 확인 |
|------|------|
| 502 Bad Gateway | EC2 `pm2 status`, nginx `/api/` 프록시 |
| 결제 return 타임아웃 | HTTPS 443, `PAYMENT_RETURN_BASE` 도메인 |
| Webhook 안 옴 | URL 공개 여부, 이벤트 타입 필터, `/admin/ops` 테스트 이벤트 |
| 알림 안 옴 | Discord URL 형식, 구독 이벤트 선택, SMTP 미설정 시 로그만 |
