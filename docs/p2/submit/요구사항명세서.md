# 요구사항 명세서 (SRS) — P2 LMS

**문서 버전**: 2.0 (P2 구현 기준, 2026-05)  
**참조**: `기획서.md`, `erd.md`, `API엔드포인트.md`, `api.yml`

---

## 1. 개요

### 1.1 범위

| 구분 | 내용 |
|------|------|
| **포함** | JWT 인증, 역할(admin/teacher/student), 공개 강의, 장바구니, 수강·취소, **영상 진도·이어보기**, Q&A, 피드백 스레드, 파일 업로드·정적 제공, 강사 강의·프로필, 관리자 통계·회원·강의 |
| **제외** | 실 PG 결제, 전용 스트리밍 CDN, 푸시·이메일 알림 |
| **산출물** | REST API, React 웹, PostgreSQL 스키마(`p2_*`) |

### 1.2 시스템 개요

학생은 공개 강의를 탐색하고 장바구니·수강신청을 하며, 수강 화면에서 진도가 저장된다. 강사는 강의와 커리큘럼을 관리하고 피드백에 응답한다. 관리자는 통계와 회원 역할을 관리한다.

### 1.3 제약

| ID | 제약 |
|----|------|
| GC-01 | 결제는 시뮬레이션(유료도 버튼 흐름만) |
| GC-02 | 영상은 URL 또는 업로드 파일 URL 기반 재생 |
| GC-03 | API 버전 prefix `/api/v1` |

## 2. 기능 요구사항

### 2.1 인증·인가

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-A01 | 이메일·비밀번호 로그인 시 JWT를 발급해야 한다. | 로그인 응답에 토큰 |
| FR-A02 | `auth/me`로 현재 사용자·역할을 조회할 수 있어야 한다. | Bearer 시 200 |
| FR-A03 | student 전용 API에 teacher/admin 접근 시 403이어야 한다. | 역할별 호출 |

### 2.2 학생 — 강의·장바구니·수강

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-S01 | 공개 강의 목록·상세를 비로그인으로 조회할 수 있어야 한다. | GET courses |
| FR-S02 | 장바구니 담기·목록·삭제 및 중복 방지가 가능해야 한다. | 409 시나리오 |
| FR-S03 | 수강신청 후 내 목록에 나타나야 하며, 동일 강의 중복 수강은 불가해야 한다. | 409 |
| FR-S04 | 수강신청 시 해당 강의가 장바구니에 있으면 제거되어야 한다. | DB/목록 확인 |
| FR-S05 | 수강 취소가 가능해야 한다. | DELETE enrollments |

### 2.3 학생 — 진도·수업

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-P01 | 수강별 영상 진도 목록을 조회할 수 있어야 한다. | GET …/progress |
| FR-P02 | 시청 초·완료 여부를 저장할 수 있어야 한다. | PUT …/progress |
| FR-P03 | 내 수강 목록에 진도율(%), 수료(active/completed), 이어보기(`last_video_id`)가 포함되어야 한다. | GET enrollments |
| FR-P04 | 완료 판정은 정책(예: 재생 90% 이상)에 따른다. | 시청 후 completed |

### 2.4 Q&A

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-Q01 | 강의별 질문 목록·페이징 | GET …/questions |
| FR-Q02 | 로그인 사용자 질문 등록·본인 수정·삭제 | JWT |
| FR-Q03 | 질문 상세·답변 목록 공개 조회 | GET question |
| FR-Q04 | 답변 등록 | POST answers |

### 2.5 강사

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-T01 | 본인 소유 강의만 CRUD할 수 있어야 한다. | teacher API |
| FR-T02 | 커리큘럼·공개 여부·가격 등을 수정할 수 있어야 한다. | PUT course |
| FR-T03 | 이미지·영상 업로드 후 URL을 강의에 반영할 수 있어야 한다. | upload + curriculum |

### 2.6 관리자

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-M01 | 통계·전체 사용자·전체 강의를 조회할 수 있어야 한다. | admin GET |
| FR-M02 | 사용자 역할을 변경할 수 있어야 한다. | PATCH role |

### 2.7 피드백

| ID | 요구사항 | 검증 |
|----|----------|------|
| FR-F01 | 학생이 피드백을 생성·조회·메시지 추가할 수 있어야 한다. | feedback API |
| FR-F02 | 강사가 배정된 피드백을 조회·상태·메시지를 갱신할 수 있어야 한다. | teacher feedback |
